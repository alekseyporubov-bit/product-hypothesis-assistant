# 🔧 Сохранение данных гипотез между редеплоями — исправление

**Дата:** 2026-09-14
**Проблема:** после редеплоя ранее введённые гипотезы пропадали.
**Решение:** JSON-хранилище (без БД) + постоянный диск + 1 worker.

---

## 🔍 Почему данные реально пропадали

В приложении **уже был** JSON-механизм (`save_to_file` / `load_from_file`), но он
не обеспечивал сохранность данных между редеплоями по нескольким причинам:

| # | Причина | Следствие |
|---|---------|-----------|
| 1 | `STORAGE_FILE = "hypotheses_data.json"` — относительный путь | Файл писался в эфемерную файловую систему контейнера, которая **полностью стирается при редеплое** |
| 2 | Запуск `gunicorn --workers 4` | 4 процесса, у каждого своя копия `HypothesisManager` в памяти → каждый затирает файл данными другого, потерянные записи |
| 3 | Запись `json.dump` напрямую в файл | Обрыв процесса при редеплое мог оставить файл повреждённым, а `load_from_file` молча стартовал пустым |
| 4 | `survey_questions` не сериализовались | В `to_dict` писался только счётчик, сами вопросы терялись при перезапуске |

---

## 🛠 Что исправлено в коде (`product_hypothesis_assistant.py`)

1. **Конфигурируемый путь хранения.** Приоритет:
   - аргумент конструктора `HypothesisManager(storage_file=...)`
   - переменная окружения `DATA_FILE` (абсолютный путь на постоянном диске)
   - значение по умолчанию `hypotheses_data.json`

2. **Автосоздание родительской директории** (`_ensure_storage_dir`) — если `DATA_FILE=/data/hypotheses_data.json`, а каталога `/data` нет, он создаётся.

3. **Атомарная запись** (`_atomic_write_json`) — данные пишутся во временный файл, затем `os.replace()`. Файл никогда не остаётся наполовину записанным.

4. **Блокировка записи** (`_storage_lock`) — `flock` на файле `.lock`, защита от одновременной записи несколькими процессами.

5. **Бэкап повреждённого файла** (`_backup_corrupt_file`) — если JSON не читается, он переименовывается в `hypotheses_data.json.corrupt-<timestamp>`, чтобы данные не терялись молча.

6. **Восстановление `survey_questions`** — вопросы анкеты теперь сериализуются (`to_dict`) и восстанавливаются (`_survey_question_from_dict`).

## 🚀 Как добиться сохранности при редеплое (на хостинге)

Кода недостаточно: JSON-файл должен лежать на **постоянном диске (volume)**, а не
в эфемерной ФС контейнера. На relaxdev.ru / Render / Railway / Fly.io:

1. **Создайте persistent volume/disk** для приложения (обычно 1–2 GB достаточно).
2. **Укажите точку монтирования** и переменную окружения:

   ```
   DATA_FILE=/app/data/hypotheses_data.json
   ```
   (или любой другой путь, куда смонтирован диск, например `/data/hypotheses_data.json`)

3. **Запускайте с 1 worker** (уже настроено в `Dockerfile` и `Procfile`):

   ```bash
   gunicorn --bind 0.0.0.0:$PORT --workers 1 --timeout 120 app:app
   ```

   При 4 worker'ах каждый процесс держит свою копию данных в памяти и затирает файл.

### Для Docker

`Dockerfile` уже содержит:
```dockerfile
RUN mkdir -p /app/data
ENV DATA_FILE=/app/data/hypotheses_data.json
VOLUME ["/app/data"]
```
Осталось примонтировать к `/app/data` постоянный том в настройках деплоя.
