## 📋 Сценарии использования

### Сценарий 1: Создание новой гипотезы

1. **Нажмите кнопку "+ Создать новую"** в левой панели
2. **Заполните форму:**
   - **Название фичи** - краткое имя (например: "Тёмный режим")
   - **Краткое описание** - 1-2 предложения о том, что это
   - **Какую проблему решает** - боль пользователя, которую устраняет фича
   - **Целевые пользователи** - кто использует эту фичу
   - **Ожидаемый результат** - какой результат ожидаем
3. **Нажмите "Создать гипотезу"**
4. Система создаст гипотезу и откроет её детальный вид

### Сценарий 2: Добавление доказательств

1. **В открытой гипотезе** прокрутите вниз до раздела "Доказательства"
2. **Заполните форму "Добавить доказательство":**
   - **Тип** - выберите из списка (например: "Обратная связь пользователей")
   - **Статус** - "Поддерживает" или "Опровергает"
   - **Название** - короткое имя доказательства
   - **Описание** - подробное описание
   - **Источник** - откуда информация (например: "Support tickets", "Google Analytics")
   - **Уверенность** - от 0.0 до 1.0 (0.8 = 80% уверенности)
3. **Нажмите "Добавить доказательство"**
4. Доказательство добавится в список выше

**💡 Рекомендация:** Добавьте доказательства разных типов:
- Market Research (исследования рынка)
- User Feedback (обратная связь пользователей)
- Competitor Analysis (анализ конкурентов)
- Analytics (данные аналитики)
- Expert Opinion (мнение экспертов)
- Case Study (примеры успеха)

### Сценарий 3: Валидация и получение Score

1. **Вернитесь к основной информации гипотезы**
2. **Нажмите кнопку "Валидировать и получить Score"**
3. **Система вычислит:**
   - ✅ **Score** (0-100) - общая оценка потенциала
   - ✅ **Рекомендация:**
     - ✓ **ИДТИ В РАЗРАБОТКУ** (score >= 70)
     - ⚠️ **ТРЕБУЕТСЯ ДОИССЛЕДОВАНИЕ** (50 <= score < 70)
     - ✗ **ОТКЛОНИТЬ** (score < 50)
   - ✅ **Разложение по факторам** - детали по каждому критерию оценки

**Факторы оценки:**
- **PROBLEM_SEVERITY** (20%) - насколько серьёзна проблема
- **MARKET_SIZE** (15%) - размер целевого рынка
- **USER_DEMAND** (25%) ⭐ - спрос пользователей (самый важный)
- **COMPETITIVE_ADVANTAGE** (15%) - наше преимущество
- **IMPLEMENTATION_EFFORT** (15%) - сложность реализации
- **ALIGNMENT** (10%) - соответствие стратегии

### Сценарий 4: Запись фактического исхода (постфактум)

1. **Через 6+ месяцев после релиза фичи**
2. **В открытой гипотезе нажмите "Записать исход (постфактум)"**
3. **Заполните форму:**
   - **Результат** - "✓ Успех" или "✗ Неудача"
   - **Описание воздействия** - какой был реальный результат
   - **Извлечённые уроки** - что вы узнали
4. **Нажмите "Записать исход"**

**Это важно для целевой метрики #3 ТЗ** - проверки корреляции score ↔ реальный успех

### Сценарий 5: Анализ корреляции

1. **Нажмите кнопку "Анализ корреляции"** в левой панели
2. **Система покажет:**
   - Количество завершённых гипотез (с записанными исходами)
   - Количество точных предсказаний
   - **Точность (%)** - процент правильных предсказаний
   - Таблица всех гипотез с сравнением score vs реальность

**Интерпретация:**
- ✓ **Если accuracy >= 75%** - система хорошо работает
- ⚠️ **Если accuracy < 75%** - нужна калибровка весов факторов

### Сценарий 6: Экспорт гипотезы в JSON

1. **В открытой гипотезе нажмите "Экспортировать JSON"**
2. **Система скачает файл** с полной информацией о гипотезе
3. **Используйте для:**
   - Интеграции с BI системами
   - Отправки stakeholder'ам
   - Архивирования

## 🎯 Типичный workflow

```
1. СОЗДАНИЕ
   ↓
   "+ Создать новую" → Заполнить форму → "Создать гипотезу"

2. ИССЛЕДОВАНИЕ
   ↓
   "Добавить доказательство" × N раз
   (собрать данные из разных источников)

3. АНАЛИЗ
   ↓
   "Валидировать и получить Score"
   (система вычислит рекомендацию)

4. РЕШЕНИЕ
   ↓
   Если recommendation == "proceed" → Идти в разработку
   Если recommendation == "investigate" → Больше доказательств
   Если recommendation == "reject" → Отклонить

5. ОТСЛЕЖИВАНИЕ (6+ месяцев спустя)
   ↓
   "Записать исход (постфактум)"
   (запишите реальный результат)

6. КАЛИБРОВКА
   ↓
   "Анализ корреляции"
   (проверьте точность предсказаний)
```

## 🔧 Системные сценарии

### При создании гипотезы

✅ Система:
- Генерирует уникальный ID
- Сохраняет в памяти (при перезагрузке - начнёте заново)
- Показывает в списке слева
- Переходит на страницу деталей

### При добавлении доказательства

✅ Система:
- Проверяет, что выбрана гипотеза
- Сохраняет доказательство
- Отображает в списке
- Генерирует уникальный ID для доказательства

### При валидации

✅ Система:
- Анализирует собранные доказательства
- Вычисляет оценку по 6 факторам
- Выводит рекомендацию (proceed/investigate/reject)
- Обновляет статус гипотезы в списке

### При анализе корреляции

✅ Система:
- Показывает статистику только для гипотез с исходами
- Вычисляет процент точных предсказаний
- Показывает, какие предсказания были неправильными
- Даёт интерпретацию точности

## 📱 Уведомления

## 🐛 Что делать при ошибках

### "Гипотеза не выбрана"
- **Причина:** Вы пытались добавить доказательство или получить score без создания гипотезы
- **Решение:** Сначала создайте гипотезу

### "Ошибка загрузки гипотезы"
- **Причина:** Сбой при загрузке данных с сервера
- **Решение:** Обновите страницу (F5)

### "Недостаточно данных" (в анализе корреляции)
- **Причина:** Нет гипотез с записанными исходами
- **Решение:** Запишите результаты для хотя бы 5-10 гипотез

## 💾 Где хранятся данные?

**В текущей версии:**
- Все данные хранятся **в памяти приложения**
- При перезагрузке страницы или перезапуске сервера - **данные теряются**

**Для production версии рекомендуется:**
- Добавить базу данных (PostgreSQL)
- Сохранять гипотезы в БД
- Реализовать аутентификацию пользователей
