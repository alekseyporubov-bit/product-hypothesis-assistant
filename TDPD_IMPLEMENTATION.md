# TDPD (Test-Driven Product Development) - Реализация

## 🎯 Что такое TDPD?

**TDPD (Test-Driven Product Development)** — это методология разработки продуктов, основанная на идее, что перед внедрением любой фичи нужно иметь **количественно обоснованное предположение** о её успехе.

### Основная идея TDPD:

```
ГИПОТЕЗА → ДОКАЗАТЕЛЬСТВА → SCORE → РЕШЕНИЕ → РЕАЛЬНОСТЬ → КОРРЕЛЯЦИЯ
   ↓           ↓              ↓        ↓          ↓             ↓
 Фича      Собрать       Оценить    Идти в    Выпустить   Проверить
 идея      факты от      потенциал  разработ   фичу       точность
          разных         (0-100)    ку                     (корриб)
          источников
```

**Примеры доказательств для "Тёмный режим":**

| Тип | Доказательство | Статус | Уверенность |
|-----|---|---|---|
| User Feedback | В support tickets 150+ жалоб на яркость | ✓ Поддерживает | 0.95 |
| Competitor Analysis | У Apple iOS 13+ есть dark mode, конверсия выше на 3% | ✓ Поддерживает | 0.9 |
| Market Research | Gartner: 72% пользователей хотят dark mode | ✓ Поддерживает | 0.85 |
| Analytics | 40% сеансов в 6-23 часов (вечерний пик) | ✓ Поддерживает | 0.98 |
| Expert Opinion | iOS разработчик сказал: это быстро сделать | ✓ Поддерживает | 0.7 |
| Case Study | Google Docs dark mode: +8% DAU, -2% churn | ✓ Поддерживает | 0.8 |

**Почему это важно:**
- Каждое доказательство = факт из реального мира
- Разные источники = меньше субъективности
- Уверенность (confidence) показывает надёжность источника

### 3️⃣ STAGE 3: СКОРИНГ (Score Calculation)

**📝 Файл:** `/Users/a.porubov/python/product_hypothesis_assistant.py` (класс `ScoringEngine`)

**Система оценивает гипотезу по 6 факторам:**

```python
SCORING_FACTORS = {
    "PROBLEM_SEVERITY": {
        "weight": 0.20,  # 20% важности
        "description": "Насколько серьёзна проблема?",
        "scale": "0-10 (0=никаких проблем, 10=критическая боль)"
    },
    "MARKET_SIZE": {
        "weight": 0.15,  # 15% важности
        "description": "Размер целевого рынка?",
        "scale": "0-10 (0=никто, 10=миллиарды пользователей)"
    },
    "USER_DEMAND": {
        "weight": 0.25,  # 25% важности ⭐ САМЫЙ ВАЖНЫЙ
        "description": "Спрос пользователей?",
        "scale": "0-10 (0=не хотят, 10=требуют)"
    },
    "COMPETITIVE_ADVANTAGE": {
        "weight": 0.15,  # 15% важности
        "description": "Конкурентное преимущество?",
        "scale": "0-10 (0=есть у всех, 10=только у нас)"
    },
    "IMPLEMENTATION_EFFORT": {
        "weight": 0.15,  # 15% важности
        "description": "Сложность реализации?",
        "scale": "0-10 (0=5 минут, 10=год работы)"
    },
    "ALIGNMENT": {
        "weight": 0.10,  # 10% важности
        "description": "Соответствие стратегии?",
        "scale": "0-10 (0=противоречит, 10=идеально совпадает)"
    }
}
```

**Пример расчёта для "Тёмный режим":**

```
PROBLEM_SEVERITY:      8/10 × 0.20 = 1.6
MARKET_SIZE:           9/10 × 0.15 = 1.35
USER_DEMAND:           9/10 × 0.25 = 2.25  ← Самый большой вклад
COMPETITIVE_ADVANTAGE: 6/10 × 0.15 = 0.9
IMPLEMENTATION_EFFORT: 7/10 × 0.15 = 1.05
ALIGNMENT:             8/10 × 0.10 = 0.8
                                    -------
                      ИТОГО SCORE = 79/100
```

**Рекомендация (по шкале):**
- **Score >= 70**: ✓ **PROCEED** (Идти в разработку)
- **50 <= Score < 70**: ⚠️ **INVESTIGATE** (Нужны доп. доказательства)
- **Score < 50**: ✗ **REJECT** (Отклонить)

## 🔄 TDPD Workflow в вебе

### Как это работает в интерфейсе:

```
1️⃣ ИДЕЯ (Welcome)
   ↓
   Пользователь читает справку о системе

2️⃣ СОЗДАНИЕ (Create Hypothesis)
   ↓
   "+ Создать новую" → Заполнить форму → Score 0/100 (нет доказательств)

3️⃣ ИССЛЕДОВАНИЕ (Add Evidence)
   ↓
   "Добавить доказательство" × N раз
   (собрать 5-10 доказательств из разных источников)

4️⃣ АНАЛИЗ (Validate)
   ↓
   "Валидировать и получить Score"
   (система вычислит score и покажет рекомендацию)

5️⃣ РЕШЕНИЕ (Decision)
   ↓
   Если PROCEED → Идти в разработку
   Если INVESTIGATE → Собрать больше доказательств
   Если REJECT → Отклонить идею

6️⃣ ВЫПОЛНЕНИЕ (Release Feature)
   ↓
   Выпустить фичу в production (если PROCEED)

7️⃣ ОТСЛЕЖИВАНИЕ (Record Outcome)
   ↓
   Через 6+ месяцев: "Записать исход (постфактум)"
   (запишите реальные метрики и результат)

8️⃣ ОБУЧЕНИЕ (Correlation Analysis)
   ↓
   "Анализ корреляции"
   (проверьте точность системы и улучшайте весы факторов)
```

## 📊 Метрики TDPD (Цели ТЗ)

### Цель 1️⃣: Сократить время подготовки обоснования

**Было:** 40 часов на документирование и сбор фактуры

**Стало:** 
- 1 час на создание гипотезы и ввод доказательств
- 15 минут на валидацию и получение score
- **Сокращение в 26x раз!** ⚡

**Как это работает в системе:**
```python
# Вместо этого (ручное написание 40 часов):
"""
Мы предлагаем добавить тёмный режим потому что:
1. Пользователи жалуются на яркость (support tickets)
2. iOS/Android уже имеют dark mode
3. Исследование показало 72% спроса
4. Это не сложно реализовать
5. Соответствует стратегии...
"""

# Система делает это (10 минут):
# Пользователь просто вводит доказательства и нажимает кнопку
# Система автоматически вычисляет score: 79/100 ✓ PROCEED
```

### Цель 2️⃣: Снизить долю неудачных фичей

**Было:** 20% фичей (1 из 5) не приносят результата

**Стало:**
- За счёт лучшей валидации на входе
- Отклонение плохих идей (score < 50)
- **Целевой результат:** 5% неудачных фичей (95% успеха)

**Как это работает:**
```python
# Плохая идея (но часто одобряется):
{
    "title": "Изменить цвет кнопки",
    "description": "Изменить кнопку с синей на красную"
}
# Доказательств: 0
# Score: 0/100
# Recommendation: ✗ REJECT ← Система блокирует плохие идеи

# Хорошая идея (с доказательствами):
{
    "title": "Dark Mode",
    "description": "...",
    "evidence": [
        "150 жалоб на яркость",
        "Конкуренты это уже сделали",
        "72% спроса по рынку",
        "Фичу просто реализовать"
    ]
}
# Score: 79/100
# Recommendation: ✓ PROCEED ← Система одобряет хорошие идеи
```

### Цель 3️⃣: Подтвердить корреляцию score ↔ реальный успех

**Гипотеза:** Если score > 70 → фича будет успешна

**Проверка:** Анализ корреляции


## 💡 Какие изменения улучшают TDPD?

Если точность < 75%, нужно **откалибровать веса факторов:**

```python
# Текущие веса:
WEIGHTS = {
    "PROBLEM_SEVERITY": 0.20,
    "MARKET_SIZE": 0.15,
    "USER_DEMAND": 0.25,  # ← Может быть увеличить?
    "COMPETITIVE_ADVANTAGE": 0.15,
    "IMPLEMENTATION_EFFORT": 0.15,
    "ALIGNMENT": 0.10
}

# Если заметили, что USER_DEMAND предсказывает лучше всего:
WEIGHTS = {
    "USER_DEMAND": 0.35,  # ↑ Увеличиваем с 0.25 до 0.35
    # остальные уменьшаются пропорционально
}
```

## 🎓 Вывод: Как работает TDPD в моей системе

| Этап | Что делает система | Результат |
|------|---|---|
| 1. Гипотеза | Принимает описание фичи | Структурированная идея |
| 2. Доказательства | Собирает факты от разных источников | 5-10 доказательств |
| 3. Скоринг | Вычисляет оценку по 6 факторам | Score 0-100 + Рекомендация |
| 4. Решение | На основе score → PROCEED/INVESTIGATE/REJECT | Обоснованное решение |
| 5. Реальность | Запись фактического исхода через 6+ месяцев | Данные для обучения |
| 6. Корреляция | Анализ точности предсказаний | Калибровка системы |

**Основной смысл TDPD:**
> Превратить **интуицию PM** в **количественно обоснованное решение** за счёт сбора доказательств и вычисления score
